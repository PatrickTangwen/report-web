# Expose read-only research tools over MCP

The research-data tools are published as a Model Context Protocol service so any MCP client (Claude Desktop, Cursor, other agents) can consume them, turning the backend from a private chatbot capability into a reusable research-data service. The transport is Streamable HTTP mounted at `/mcp` on the existing FastAPI application — one container, one port, because Render exposes a single HTTP port and a second entrypoint would not be reachable; the MCP session manager runs inside the host app's lifespan since a mounted sub-app's own lifespan never executes. The server is stateless with JSON responses, which matches a public read-only service on a platform whose instances may restart, and DNS-rebinding protection carries an explicit Host allowlist (the Render domain plus localhost). A stdio entry (`python mcp_server.py`) serves local development. The roster is a strict superset of the in-task agent's: the five Study Evidence tools plus `search_icd_codes` (whose UI surface stays on visualization pages per ADR-0010 — exposing it to external tools does not reintroduce it into the Assistant) and raw access to the display-safe fibrotic release. The governance boundary is absolute: the profile/matching flow, the private matching artifact, and anything patient-level are never registered on this surface, and every call routes through the same Pydantic validation layer the agent uses (`execute_tool`), so the two surfaces cannot drift. The `mcp` dependency is pinned to 1.x because mcp 2.0 requires starlette ≥1.x, which conflicts with the deployed fastapi 0.115 pin; upgrading both together is a deliberate future change, not a drive-by.
